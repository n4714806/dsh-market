# Portable Market — 完整可攜修正版（非官方）

這個分支是可以直接安裝的完整外掛套件，不是小 patch，也不需要原電腦的資料夾。版本 **0.4.17-portable.6**，基於 `@dsh-market/plugin` 0.4.17。

完整交付內容、發布包下載與驗證限制，見 [交付與驗證說明](docs/DELIVERY.md)。

## 在家裡的電腦安裝

1. 安裝／開啟 DeepSeek Harness，建議使用已實測的 **0.2.1-rc.5** 或符合套件版本需求的版本。
2. 若已裝另一份外掛市場，先在 Harness **內建「外掛」管理頁**移除 `@dsh-market/plugin`，不要從市場自己的按鈕移除自身。
3. 在內建「外掛」的新增安裝來源中輸入：

```text
github:n4714806/dsh-market#portable-v0.4.17.6
```

4. 完成後重新整理／重開 Harness。語意搜尋會使用那台電腦的全域預設模型，請自行設定／登入 AI 供應商。

固定版本原始碼：https://github.com/n4714806/dsh-market/tree/portable-v0.4.17.6

如果 Desktop 的新增介面只接受本機資料夾：下載上述固定版本的 ZIP、解壓縮，再將套件根目錄交給內建外掛管理器安裝。讓管理器處理 production dependencies，不要手改 profile 設定。

CLI 已安裝且可用時，可在**目標 profile**執行（下例的 `web` 請換成實際名稱）：

```sh
dsh plugin --profile web add github:n4714806/dsh-market#portable-v0.4.17.6
```

不需要在家裡重現修正過程，也不要執行這個上游大型 repository 的一般開發建置命令。此分支根目錄本身就是已建好的 bundle，沒有 prepare/install/build lifecycle scripts。

## 包含的完整修正

- 一般 Cordis 外掛安裝、更新、移除走宿主外掛管理器，不依賴外部 `dsh` 命令。
- 以宿主目前 profile 為準，拒絕跨 profile 誤操作；不寫死 desktop/web。
- 精確辨識目前 profile 的已裝套件；市場資訊有歧義時保留真實套件名管理，不胡亂對應另一個外掛。
- 顯示真實安裝階段、錯誤、重啟需求；狀態查詢有上限，不把未知／逾時當成功。
- registry 更新失敗時嘗試還原精確舊版與原 enabled 狀態，還原結果明確顯示。
- 語意搜尋跟隨全域預設 provider/model/reasoning effort，顯示模型與降級原因，具有逾時保護。
- 包含回歸測試；production dependencies 固定為已測版本。

## 相容修補工作台（portable.6，第一階段）

市場新增「相容修補」頁，和 `market_compat` Agent 工具使用同一個 Host 控制器：

- 「診斷相容來源」只讀公開 npm 宣告，優先找宣告相容的官方版本，不呼叫模型、不安裝。宣告相容不代表功能已驗證。
- 使用者額外選擇 AI 才會準備草稿：當下全域預設模型、最多一次生成請求、4096 輸出 tokens、模型階段 90 秒。不是美元費用硬上限；取消或逾時仍可能已計費。
- 每次診斷最多一次生成嘗試，失聯後重送或換 requestId 不會重複生成；若確實要重做，先重新診斷。
- AI 沒有工具或代理權限，只回傳嚴格 JSON。Host 驗證來源完整性、相對路徑白名單、唯一前文與大小；不執行原始碼、shell、建置腳本、安裝腳本，不自動改版本限制。
- 產物是「未驗證草稿 JSON」，附來源鎖定、模型資訊及修改前後雜湊，可複製匯出；**不是完整可安裝的修補套件**。沒有安裝、版本豁免或重啟端點。
- 結構檢查與語法／執行／畫面測試分開顯示；目前後三者未執行。安全隔離建置、實機功能驗證、確認後安裝及回復屬後續階段，沒有假裝完成。
- 任務保存於目前 profile 對應的工作台資料區；重啟會標示中斷，不自動恢復或重試。最多 50 筆、journal 2MiB、每份草稿 256KiB，滿額即停止，不清掉冪等歷史。
- 「檢查上游」只比對版本／來源雜湊，不自動重套 patch 或啟動 AI。對外發布任何草稿前仍須人工確認授權及風險。
- 第一版僅支援公開 npm HTTPS 來源；來源讀取有時間／大小／完整性限制，不安全或不支援的 tar 格式明確停止。HTTP 入口限制本機連線與本機 GUI authority、JSON 同源請求；遠端操作可走受宿主政策管理的 Agent 工具。

首個 Better Sidebar 案例：0.30.1 宣告需 DSH 0.2.2-rc.1 系列，對 0.2.1-rc.5 會找出官方 0.28.2，而不是硬造 patch。這只是版本宣告診斷，未安裝或執行該外掛。

## 精確更新與版本核對（portable.5）

不再只用 `@latest` 並將套件管理器的成功退出當成升版成功。每次更新從宿主相同 registry 重新查來源、指定精確版本，完成後直接重新讀取宿主的已裝套件清單；已裝版本必須等於目標才報更新完成。若來源版本已與畫面不同，先停止並請重新檢測。

成功、失敗與回復後都重新載入清單，每列保留當次操作的目標／實際／API 回報版本及結果，可再按「重新檢測版本」。版本未變、更成其他版本或無法讀取，都不會假報更新完成。需要重啟時明確區分「安裝檔版本已核對」與「宿主仍須重開才能載入」，只提示手動重開，不會自動重啟。

保留宿主相容性、建置批准與發布時間政策；不降低 minimumReleaseAge、不授予版本豁免。現有宿主尚無原子替換 API，安裝失敗會嘗試還原原精確版本，並再次核對還原結果；可能仍需內建外掛管理處理。

## 繁體中文介面（portable.4）

選單、按鈕、提示、錯誤訊息及可見分類採繁體中文，並使用外掛、設定、使用者、搜尋等台灣用詞。主介面使用獨立 Client locale namespace 與 OpenCC 衍生的顯示層字典，不變更 Harness 的全域語言偏好。

只改顯示：API 識別、搜尋分類原始 key、表單值、網址、安裝命令與複製的原始診斷維持不變；程式碼、命令及原始診斷區塊刻意保留原文。既有更新／安裝／還原邏輯不變。

字典授權與來源見 THIRD-PARTY-NOTICES.md。字典已隨包附帶，安裝時不需 Python、OpenCC、建置腳本或原電腦路徑。開發時可用 `pnpm run build:zh-tw` 重建主前端及相容前端；若重產字典，先在隔離工具目錄安裝 `opencc-python-reimplemented==0.1.7`，再執行 `python scripts/build-zh-tw.py <工具目錄>`。

## 已裝清單直接更新（portable.3）

進入「已裝」就會自動檢查來源版本；「檢查更新」可略過快取。每個套件直接顯示目前版本、可更新版本、檢查中／失敗／已符合來源等狀態。

安全可更新的 registry 套件旁會出現「一鍵更新」，點擊才執行宿主更新；成功後重新讀取清單與版本，失敗明確顯示還原結果。不會自動更新全部套件、不會批准額外腳本，也不會因查詢發現新版就直接安裝。

Git、本機、別名、受保護或無法精確還原的來源會顯示不可一鍵更新原因；查到新版與可以安全更新是兩回事。fork 市場自身不得誤顯示「portable → 官方版」升級，包含仍呼叫舊版 self-update API 的前端。

可用 `client:build` RPC 查驗 Host 真正提供的 Client artifact，而不是只看套件版本號；API 回應不代表瀏覽器已重新載入。已快取舊 Client 路徑的 Host 也會取得相同新版內容：發佈保留同步的相容檔，啟用時透過宿主 `clientModules.rebuilt` 發布完成的 artifact。更新後請重新整理 GUI，確認出現「任務追蹤版 .5」。

## 任務追蹤與來源版本（portable.2）

- 「安裝任務」可重新開啟，顯示階段、時間線、結果、錯誤和完整子會話 ID；只在分頁可見時每 3 秒查詢，15 秒無回應會明確報錯。
- 任務先落盤才開始操作。保留最近 100 筆、每筆 50 個事件；保留已用 ID 的雜湊以避免重複執行。重啟時未完成任務標為「已中斷」，不自動重試。只支援單一 Host 寫入同一 profile。
- AI 審查／診斷必須明確選擇父會話，並確認真實子會話與結果管道後才稱為委派。非原生外掛的 AI 路徑只要求診斷，不會由市場自動執行模型建議命令。完整建議留在子會話，不存入任務診斷副本。
- 取消表示已提出停止要求，不等於所有變更已回復。逾時、停止狀態不明及重啟需求會顯示「需要處理」。舊版未保存的歷史任務無法補回。
- 安裝視窗分別查詢 npm `dist-tags.latest` 與 GitHub 最新正式 release，顯示來源、查詢時間及快取狀態；可手動略過 5 分鐘快取。查詢失敗、限流、找不到 release 都不是「已是最新版」。
- 已裝更新檢查優先使用宿主**明確設定的 registry**，其次才是 pnpm 解析來源；不拿 GitHub 修改時間替代失敗的 npm 查詢。Git／本機來源不假裝可比較 npm 版本。
- 市場首頁顯示索引生成時間，並可重新取得索引。**這不是全市場即時同步**：新條目收錄仍受上游索引發布進度影響；GitHub release 與 npm 是不同發布渠道，不保證版本號相同。
- fork 使用固定 tag，不以官方市場 npm 版本判斷自我更新。更新此市場請用內建外掛管理；安裝後重新整理／重開 GUI，確認看得到「安裝任務」及「任務追蹤版 .5」。

## 不包含個人資料

沒有攜帶帳號、API key、OAuth token、聊天、桌布、profile、原電腦絕對路徑或 node_modules。安裝套件仍需要網路下載依賴；家中電腦的 AI 登入需自行完成。這不是離線攜帶整個 Harness 的備份。

## 驗證及限制

- 已在 Windows 的 DSH 0.2.1-rc.5 Desktop 驗證。
- 真實隔離 CLI／Web 測試通過：安裝、精確清單、啟用、更新、刻意失敗後還原、移除、跨 profile 拒絕。
- UI 函式有 mock 回歸測試；沒有宣稱瀏覽器畫面、第三方桌布效果或其他作業系統皆已驗證。
- 純 headless CLI 沒有市場 Web UI；此套件仍需要 Web Host。
- 市場自我更新／移除、安全審查後安裝、需要額外 build-script 批准等情況，請使用宿主內建外掛管理。
- 技能、MCP、備份匯入等特殊流程仍保留原市場實作，未全數遷移。
- 更新還原不是斷電交易保證；無法精確還原的 Git／本機來源更新會提示手動處理，不先移除。
- 不繞過宿主版本檢查或自動批准執行腳本。

## 開發與測試

有 Node.js 即可執行不需網路的 mock 測試：

```sh
npm test
```

這個 portable branch 與最小上游 PR 分支不同：`fix/scoped-inventory-default-model` 只包含兩個窄範圍的原始碼修補；要跨電腦使用完整版本，請用這個 portable tag。
